# Onboarding & Setup 验收

在正常Codex用户配置下实际调用Skill。测试不能新建仓库、申请权限、试写、自动保存虚构成员身份，不能因MCP配置存在就宣布连接成功。

| 场景 | 可观察结果 |
| --- | --- |
| 首次功能介绍 | 自动选择Skill，使用first-introduction.md介绍三项用户能力及示例，邀请检查但不读取个人配置或调用GitHub |
| 已确认项目与成员 | 复用本次用户明确确认的绑定/署名，不重复初始化；实际MCP读取项目 |
| 未绑定项目 | 不沿用开发示例、不猜测仓库，询问正确共享地址 |
| 只读连接 | 使用官方只读端点读取；仍可查询，不能据其读成功或底层令牌范围宣称可同步 |
| 缺project.md | 真实读取目录/记录，不编造正式目标、成员名单或规划 |
| 认证失败 | 真实初始化错误与配置/绑定/成员状态分开提示，不自动扩大权限 |
| 错误地址 | 格式不完整先询问，不对猜测地址发请求 |
| 无GitHub连接 | 当前运行环境禁用GitHub连接时给引导，不把已指定仓库当连接成功 |

只读端点测试不等于签发并验证新的只读PAT；临时禁用连接/明确不选项目属于受控运行配置场景，不能描述为新机器安装实测。不同真实GitHub账号、空仓库与实际缺写权限的令牌场景如果未执行，须单列未测试。

证据：docs/poc/onboarding-setup/。状态以真实工具事件、启动错误和回答联合判断，不仅依据AI自述。


## 个人配置跨会话回归

先在用户目录保存一次本人已确认配置；使用独立新Codex会话，仅给出“介绍功能并查询已连接项目进展”，不得在Prompt提供署名、完整配置或重复要求用户填写。核对实际Skill读取、read-profile.py的ok返回、MCP读取已保存项目、恢复本人署名及无重复初始化。保存真实事件及配置前后指纹；无远端写入。

tests/test_setup_profile.py中的权限拒绝、缺文件等为受控单元测试，不是实际Windows权限模拟成功。真实Access denied及单文件只读授权后的独立会话测试另存报告，保留失败证据。


V3.1之后，“已配置项目直接使用”须在会话明确项目或明确恢复默认绑定；只有旧profile时先确认当前目标。纯介绍与连接检查拆分，先前介绍即查配置的验收行为为历史基线，不是V3.1预期。新增七项场景及证据规则见 v3.1-introduction.md。
