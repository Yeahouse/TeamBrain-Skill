# Work Sync 行为验收

仅在 Yeahouse/teambrain-test 测试。预览与取消阶段不得调用任何写工具。当前对话给出的虚构讨论是测试输入，不代表真实团队工作；不得编造已确认或已上传状态。

| 场景 | 验收要点 | 当前验收边界 |
| --- | --- | --- |
| 正常讨论形成结论 | 实际加载Skill/MCP，提炼工作与结论，列真实附件、唯一稳定ID和路径；确认后才能写及回读 | 先测预览，用户确认后再验完整同步 |
| 多次修订方案 | 已否定/暂不采用/最终决定分开，不能补造方案被否定的原因 | 先测预览，用户确认后再验完整同步 |
| 没有正式结论 | 输出探索记录，不把建议当正式决策，用户排除成果后不上传该成果 | 先测预览，用户确认后再验完整同步 |
| 修改与取消 | 同一真实会话中修改、刷新预览、保持ID、取消标记，MCP核对无新增 | 取消通过不得以实际上传证明 |
| 重复/冲突 | 真实读取同一ID；完全相同不再写，内容不同时停止并另行确认 | 保留首轮冲突输入与精确重复对照的独立证据 |
| 写入拒绝/结果未知 | 不虚报成功；未知先读远端，内容一致不重复，仍不可读不重试 | 本地 evaluate_receipt 受控测试；不是GitHub故障实测 |

来源证据：docs/poc/work-sync/。包内文本是待确认内容，不是上传回执；成功必须有真实 push_files 响应、Commit ID 和MCP固定提交回读核验。
