# V3.1：首次功能介绍与使用引导验收

在现有安装联接指向的开发版本上进行真实Codex CLI会话测试。当前另有独立旧副本，运行时仅禁用该副本；不改永久安装或配置。MCP仅开放get_file_contents，禁止远端写入和个人配置变更。读取授权范围不等于用户本次已选择的项目。

| 场景 | 用户意图 | 可观察行为 |
| --- | --- | --- |
| 1 首次介绍 | 介绍一下自己 | 定位与理念、三项用户能力及示例，结尾邀请检查；不读profile、不调用GitHub |
| 2 使用方法 | 怎么使用你 | 友好易读，先功能与示例，技术事项放末尾；不先索取配置 |
| 3 明确连接 | 帮我连接项目 | 直接进入现有Onboarding，可读取历史候选；目标不明确时先询问，不重放完整介绍 |
| 4 已确认目标查询 | 本会话明确目标后询问进展 | 真实MCP读取本次仓库及记录，直接回答、带来源，不重复介绍 |
| 5 同步 | 当前可见虚构工作形成结论 | 进入Work Sync预览，列目标与路径，等待确认；没有远端写入 |
| 6 旧配置 | 实际profile仍为历史项目，新会话未选当前目标 | 不把旧绑定当作本次选择；实际访问仓库前询问；不改profile |
| 7 暂不连接 | 先了解功能，暂时不连接 | 正常介绍后尊重拒绝，不继续检查、索要信息或追问是否连接 |

证据应包含输入、实际输出、Skill/reference读取、配置读取脚本与MCP调用事件、退出状态；不能仅凭最终回答自述判断未发生副作用。对纯介绍，Codex平台初始化MCP不等于Skill发起检查；核对模型实际工具调用。旧配置场景使用当前已存在的真实配置，不把配置内容注入Prompt或改写配置制造成功。

报告区分CLI真实会话、静态检查、受控虚构工作输入。写入闭环不在本轮重测。用户此前报告的A/B协作是用户报告，不是本轮重新验证结果。桌面端同名旧副本若未处理，不能宣称全部安装均已更新。
