## 2026-10-21：个人配置复用最小修复及最终验收

09的原始失败证据保留。新增10、11两个独立正常Codex CLI会话均通过：实际加载安装的Skill，运行read-profile.py，返回ok并恢复Cyan、Yeahouse/teambrain-test/main，随后通过官方GitHub MCP读取记录正文并回答进展/成果；没有重复询问已有配置。测试Prompt不含Cyan、仓库名或完整JSON，未用Prompt注入模拟配置复用。具体调用数与校验见profile-fix-verification.json，完整事件与答复见10/11文件。

真实根因：个人文件与两级父目录原ACL仅授予当前用户、管理员和SYSTEM；当前用户可读，但legacy elevated沙箱使用的CodexSandboxUsers无此文件读取授权。codex doctor确认elevated、restricted，未配置deny-read规则。不是路径不存在或JSON损坏。之前的Test-Path遇Access denied后仍进入else输出Profile not found，导致误报；读取器现区分权限、缺文件、其他读取错误及格式问题。

最小权限修复：仅在现有profile.json增加CodexSandboxUsers的Read（Windows显示Read, Synchronize）允许项，不继承、不授予写入、不修改父目录ACL、不修改其他项目及全局安全策略。未使用Full Access或关闭沙箱，也未复制配置到Skill/GitHub。现有配置内容未重写，指纹在两个会话前后保持一致。该ACL使本机Codex沙箱身份可读此文件；不同系统或后端仍需按实际权限处理。若以后通过替换文件更新配置，需检查单文件授权是否保留。

新增scripts/read-profile.py只返回当前项目必要已确认字段；references给出读取方法、状态处理及授权边界。该.profile路径是TeamBrain约定，不冒称Codex官方内置配置。普通成员不需要在每个会话重新填资料。原github认证问题未修复，本轮仅临时开放已验证测试连接的get_file_contents，不调用写工具。

17项单元/回归测试通过（新增7项profile、原有10项Work Sync）；独立会话为真实实测，单元测试中的PermissionError等为受控输入。最终Skill格式、Git差异检查和敏感信息审查另见本目录review及validation证据。Onboarding基础验收及本机跨会话恢复现已通过；新机器、第二真实GitHub身份与新只读PAT等此前未测项目继续保留限制。
