# TeamBrain R8.1：GitHub 官方 MCP 只读连接实测

测试日期：2026-10-21（Asia/Shanghai）

## 结论

官方 Remote GitHub MCP 已通过 Codex 客户端真实调用验证。按顺序读取了 `Yeahouse/teambrain-test` 的 `README.md` 和 `Yeahouse/TeamBrain-Skill` 的 `SKILL.md`，两份返回正文与本地对应文件一致（比较时统一 CRLF/LF）。本次未写入测试仓库，未修改 Skill 或 R7 存储结构。

## 环境与连接

- Codex CLI：0.163.0-alpha.10.2。
- 配置位置：用户目录下 `.codex/config.toml`，本报告不公开个人绝对路径。
- 传输：Streamable HTTP；官方端点 `https://api.githubcopilot.com/mcp/x/repos/readonly`。
- 配置仅引用 `GITHUB_PAT_TOKEN` 环境变量名；不包含令牌值或授权头。
- 授权前：服务可达，未认证请求返回 401；Codex 初始化报告环境变量未设置，工具列表为空。
- 授权后：测试进程从本机用户环境加载令牌，Codex MCP 初始化成功，`toolsError=null`，返回 13 个只读工具；没有开放写入工具。
- Remote 可用，因此未安装或启用 Docker 方案。

## Skill 文件读取问题的诊断

先前独立 CLI 使用 `--ignore-user-config`、`read-only`、approval never，读取命令在启动前被执行策略拒绝。之后保留正常用户配置及 Windows 沙箱设置，使用常规 `workspace-write` 模式并明确禁止文件修改，实际调用 `$teambrain`，成功读取入口、记录格式和虚构讨论文件；文件读取命令退出码为 0，返回了真实正文。

因此正常配置下 Skill 可以读取工作区，失败属于独立测试的运行配置/执行策略层，不能归因于 Skill 设计。由于对照同时改变了配置加载和沙箱模式，尚未确定单一选项是否为唯一根因。完整 CLI 日志保留本地，因包含个人路径且不属于此次 MCP 只读调用的必要原始证据，不随本次提交上传。

## 验证范围与限制

- 真实通过：工具发现、两个指定文件的 MCP 读取、正文与本地内容比较。
- 没有验证：写入权限、Markdown 写入、附件上传、并发、重复提交、失败恢复。
- 本次通过临时 Codex 客户端验证；现有桌面进程的环境继承和工具列表刷新需另行确认。
- 当前只读配置不能直接进行写入验证；需要单独批准测试仓库写权限和必要工具。
- Skill 源码保持原样；未开展 R8.2/R8.3。

## TeamBrain V1 工具分工

仓库查询和 Markdown 同步优先验证官方 MCP。开发备份及二进制成果上传由 Git CLI 补充。当前 MCP 文本写入工具的 content 为文本字符串，不应假定传入 Base64 会自动保存为原始二进制文件；写入和附件路径均须实际回读核验。
