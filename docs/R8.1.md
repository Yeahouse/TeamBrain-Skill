# R8.1：验证一条记录的可靠保存

## 顺序

1. 核对 GitHub 登录账号、两个仓库的内容与权限。已有仓库先克隆，再添加骨架，发现同名文件则停止核对。
2. 在当前对话提供一段虚构阶段讨论，要求 TeamBrain 生成记录草稿，检查结论是否忠于输入。
3. 用户确认目标为 Yeahouse/teambrain-test，确认草稿及附件后才提交。先使用一条记录和一个小型文本附件。
4. 从远端回读记录及附件，比较提交 ID、附件字节数与 SHA-256；记录提交 SHA 与结果。
5. 相同 ID 再执行一次：应识别重复；修改原记录时应保留历史。
6. 模拟附件缺失或上传失败：应明确部分完成，不生成虚假成功链接。
7. 两个独立克隆各写不同记录：验证非快进推送被拒绝后的读取与恢复；同一记录冲突交由人工处理，不强推。
8. 中断后的重试先读取远端，不重复提交；记录失败原因与恢复结果。

## 完成标准

一条经过用户确认的记录和一个真实附件在远端可回读，附件校验一致；重复识别与一次失败恢复有证据。并发验证单独记录，不以目录隔离替代验证。

复杂任务管理、长期记忆、自动后台同步、数据库、复杂并发调度、多平台完整适配。
