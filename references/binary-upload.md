# V3.5 真实成果文件：单一Git补充路径

当前GitHub MCP连接仅提供get_file_contents与push_files；后者只有文本content字段，没有二进制编码参数，不能把Base64字符串当原文件。存在其他服务器不代表当前可调用。本版不扩工具、不开发REST/LFS/多备选上传器，二进制统一用scripts/upload-work-sync.py调用已有Git CLI，文本-only仍走MCP。

## 识别范围与支持

只检查当前用户已确认的项目工作目录、当前对话提到的输出目录/文件，按需列一层文件或特定成果子目录；不遍历用户主目录、其他项目、历史会话或无关私人文件。尚未给定合理范围、文件与本阶段关系不明或同名多版本时简短询问。发现文件不是上传批准，展示候选让用户排除。

支持原样字节的DOCX、PDF、PPTX、PNG、JPG/JPEG、GIF、WEBP；原UTF-8 Markdown/TXT继续支持。其他类型明确不支持，不改扩展名、不提取正文伪装原文件、不自动生成替代成果。按原始字节处理不等于验证文档可打开、去除隐藏元数据或完成内容脱敏；原文件隐私/嵌入内容须由用户审阅，脚本只阻止常见明文凭据特征。

本版保守上限每文件25 MiB、整个上传包100 MiB；不是GitHub平台最大值。超限停在预览，可建议外部可分享链接，不自动压缩/分片/LFS。符号链接文件、可疑文件名或父路径冲突停止；不扫描未列入包的本地文件。所有成果继续保存records/<id>/artifacts/<文件名>，无根目录重复副本；外链仍按原规范保留记录中。

## 复用草稿与生成上传计划

prepare-work-sync.py仍以同一个输入/输出维护submission_id、request_key、created_at；新增binary_files保存本地来源、目标路径、字节数和SHA-256，files仍只含记录与文本。二进制内容不进入聊天或JSON，只有本地来源路径保留在忽略的tmp/work-sync草稿中，不上传整个packet。

选定项目和署名仍必须调用V3.2的resolve --require-member，不能从文件目录名决定仓库。源文件或候选改变时更新同一草稿并重新确认；已保存且未变的草稿不重复提炼。旧草稿增加二进制是内容/文件清单改变，即使ID相同也须重新确认。

从实际Skill目录执行，用户工作目录不同则使用脚本完整路径：

```text
python scripts/upload-work-sync.py plan --packet <现有packet.json> --repository owner/repo --branch <已确认分支> --member <该项目署名> --output <新的本地plan.json>
```

plan完全离线，锁定目标、分支、署名、整个packet和每个文件字节指纹。需向用户展示项目名称（来自已确认绑定）、仓库/分支/署名、完整记录预览、每文件类型/名称/大小/相对目标路径和SHA-256，明确“本次含二进制，将改用Git单提交上传整个包；Git授权与MCP授权是不同通道”。保持原记录正文，不先经MCP写记录再补二进制。

用户批准该具体内容和Git机制后才执行：

```text
python scripts/upload-work-sync.py upload --plan <plan.json> --confirm <对应confirmation_sha256>
```

摘要只是内容锁，不代表人类批准；AI不得自行通过摘要获得授权。取消、只批准初始化、原计划已撤销时不执行；改目标/分支/作者/附件或机制需重新预览确认。执行前再次用resolve核对本会话目标及署名与计划一致，不自动修改profile。

## 认证、写入与安全边界

复用当前用户已有Git凭据助手及Git提交身份，不读MCP Token、不调用gh auth token、不复制凭据到URL/配置/日志、不修改Git全局配置。MCP读取成功不代表Git身份相同或Git可写；Git缺认证/提交身份时停止，让用户按实际通道自行授权，不默认新建Token。本版不自动配置认证。

脚本仅使用https://github.com/owner/repo.git，独立系统临时Git仓库和索引，fetch既有目标分支；分支不存在或空仓库会停止，先按V3.4单独预览确认初始化，不借二进制上传自动创建首提交。初始化后保留原计划/草稿；内容与批准范围不变即可接续。

在读取的远端提交上检查同一记录ID：完全一致则返回已存在并核验；部分存在、不同、额外同ID文件或父路径类型冲突则停止，不覆盖/补写。直接以hash-object --no-filters写原字节到Git对象，再合并记录/文本/二进制为同一新提交，不运行工作区过滤器或项目hooks、不暂存用户项目其他文件。仅普通非强制push；推送前核对分支头，更新/冲突停止，不自动拉取重做或重试。此基础检查不等于完整并发保证，目标分支同时被删除/重建等极端竞争未覆盖，遇异常先回查。

只有执行upload会连接或写入远端。临时Git对象由Git正常管理；退出清理自身临时目录，不删除用户工程。所有Git stderr不展示，避免凭据助手原始报错泄露秘密；失败时给认证/网络/身份/分支待核对的受限状态，不凭模糊错误断言某一原因。标准收据只有路径、文件类型、预期大小/哈希、逐文件状态、真实提交及链接，不输出本地来源或凭据。

## 回读与部分结果

推送后从另一个全新临时Git仓库fetch同一远端分支，只有读到本次Commit ID且每个blob原始字节、大小和SHA-256完全一致才报告成功；不是用已有本地对象冒充远端核验。不使用Git LFS指针、下载链接或文件名证明原始文件已上传。后续查询仍可用MCP读取记录和成果路径；大二进制核验以Git实际回取字节为准。

分开列记录、文本附件、真实文件各自状态：已核验、缺失/不同、未上传、结果未知。一次普通分支推送通常使整份包同时可见，但不能据此忽略回读失败；仅部分确认时明确报告，记录清单只是提交前预览，不追加提交来伪改状态。

推送异常后脚本只回查、不再次push；若分支没有指向本次提交或回读失败，返回结果未知并保留candidate_commit/同一记录ID，不能报成功。由AI通过MCP/Git只读检查同ID及真实内容后再决定是否需要修复预览。禁止直接再次执行upload试运气，不能生成新ID掩盖部分结果。保留本地packet/plan与标准收据，不上传原始进程日志。

## V3.6 恢复检查与本地回执

CLI upload默认在plan.json旁保存plan.json.receipt.json，库函数execute也必须显式提供本地receipt_path（未提供则在联网前停止），也可用--receipt指定新的本地回执路径。仅放在忽略的tmp/work-sync内，不纳入共享仓库。写前回执记录同一目标/署名/ID、确认摘要、文件清单和candidate_commit，推送发生前即记“结果未知”；进程中断仍可定位该次请求。已有回执一律阻止同路径直接再次upload，不删除旧回执或自动重试。草稿和plan保持不变，回执不复制秘密或本地成果源路径。

恢复先重新确认本会话项目与原plan一致，再运行只读命令：

```text
python scripts/upload-work-sync.py inspect --plan <原plan.json>
```

inspect仅fetch，不提交、不push，按plan中的已批准目标路径、大小与哈希检查同ID文件，源文件本地暂不可用时仍能检查远端；这不授权再次上传。全匹配无需写入；部分/内容冲突/同ID额外路径先展示状态，不自动补齐；远端不可读保持未知；全部缺失时向用户说明前次状态，获明确重试批准后才选择新回执路径使用同一草稿，不覆盖旧回执。当前没有自动修复或自动重试机制。检查结果是快照，重试前仍检查最新状态。

回读分文件保留remote_bytes/remote_sha256与状态，一项blob读取失败不抹掉其他已核验项。另一成员追加无关提交导致HEAD前进时，检查最新快照内本记录的真实内容；完整一致可报告在该快照核验成功，同时区分candidate_commit和核验commit，不误称本次提交覆盖了后来的版本。错字节/类型或同ID额外文件时停止；原提交已存在但后来被改时也不称成功。

普通非强制push继续作为基础版本冲突保护；未增加锁服务、队列或分支删除/重建场景的原子条件保护。原V3.5真实DOCX结果不代表本轮恢复或并发场景已远端验证。
