# 查询与同步共用的项目目标解析

单纯介绍TeamBrain不读profile或本参考；保持V3.1的“先介绍，征询是否检查”。实际项目管理、查询和同步都调用同一scripts/read-profile.py，不另写目标猜测规则。

## 优先级与确认

1. **当前指令明确指定项目**：`resolve --explicit owner/repo`或项目名称，核对对应绑定和署名。当前指令优先于本会话旧目标；一次性指定不自动改变持久默认项目。地址有效但未绑定时返回target_unbound，可按明确授权对该仓库只读查询并说明未绑定；同步需另行确认该项目作者，不能借用旧项目署名。
2. **本会话已有用户确认目标**：`resolve --session owner/repo`，继续使用，不重复询问。不能把聊天主题、GitHub账号、上次读取、列表排序或保存的active_project当作会话确认。
3. **用户明确恢复已保存默认项目**：`resolve --use-saved`，展示恢复的项目和署名，可复用配置。此选项只用于用户明确恢复意图，不能为跳过确认擅自使用。
4. **仅存在一个或多个历史项目**：直接resolve返回needs_target_confirmation，展示项目名称、仓库和各自署名并问使用哪个。只有一个历史项目也不自动确认。目标未定时先只确认项目，不把“尚未选择哪份分支/署名”误判为字段缺失；用户选定后直接复用该项目已保存的分支和署名，只有确实缺失才询问，不要求重新填写。用户选择后在本会话复用，不反复问。
5. **缺文件或没有项目**：提示添加；用户提供地址后可生成本地绑定预览，确认才保存。权限、损坏或未知版本如实报告，不编造已连接状态，不自动覆盖。

同名项目返回ambiguous_project时通过owner/repo消歧。查询可不设置成员，Work Sync解析加`--require-member`；member_required时询问当前项目署名，不从其他项目、GitHub或虚构作者填充。

## 向下游传递同一目标

resolve返回目标的name、repository、branch、member和preferred_connection；查询与同步都使用这些字段。分支未确定时不凭历史项目猜测；显式未绑定仓库可使用MCP默认分支读取并说明，保存前确认分支。工具可见、地址已保存、GitHub实际可读与实际可写是不同状态，remote_access默认未验证，真实读取后才报告本次结果。

Work Sync预览必须明确项目名称、owner/repo、分支、该项目的成员署名以及所有记录/成果路径；用户批准这份具体预览后才可能写入。更改目标、分支、身份或内容须刷新预览并重新确认，不能沿用另一项目的批准。切换项目或改署名不修改既有远端历史记录。

历史开发示例不构成新会话默认项目或访问授权。不因Skill位于开发工作区就读取旧测试仓库；也不将Skill源码仓库自动作为团队数据源。不新建GitHub仓库、不改变R7的project.md、records/、artifacts/、links/结构。


协作恢复也使用上述目标解析：原plan/回执只证明曾批准的项目，不能自动成为新会话当前项目。先确认本次目标与原仓库/分支/署名一致；不同则停止原请求并重新预览，不将A成员记录改署名为B、不复制其他项目的回执或授权。查询仍按远端记录实际作者和来源回答，不因本地当前身份覆盖历史作者。
